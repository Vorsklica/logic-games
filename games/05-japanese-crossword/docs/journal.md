# План завершення редактора японських кросвордів

## Мета

Перед початком розробки гри завершити редактор, реалізувавши функцію **«Експорт»**, яка формує готові дані для гри.

---

# 1. Формат зберігання документів редактора

Редактор продовжує працювати **лише** з файлами формату `*.draft`.

Папка `editor/drafts` залишається основним сховищем документів редактора. Перенесення файлів до папки `accepted` більше не використовується.

---

# 2. Призначення команди «Експорт»

Команда **«Експорт»** створює готовий набір даних для гри у папці

```
content/data-XXX/
```

де `XXX` — автоматично визначений номер набору.

Редактор і гра залишаються незалежними один від одного.

* редактор працює тільки з `*.draft`;
* гра працює тільки з експортованими даними.

---

# 3. Структура експортованих даних

У кожній папці

```
content/data-XXX/
```

створюється один файл

```
data.js
```

який містить всю інформацію про задачу.

Приблизна структура:

```javascript
export default {

    meta: {
        sourceFile: "Ракета.draft"
    },

    title: "Ракета",

    width: 15,
    height: 15,

    bitmap: [
        ...
    ]

};
```

### Поля

* `meta.sourceFile` — ім'я файлу `*.draft`, з якого виконано експорт;
* `title` — назва задачі;
* `width`, `height` — розміри поля;
* `bitmap` — бітова карта задачі.

Підказки (`rowHints`, `columnHints`) **не зберігаються**. Гра генерує їх самостійно за допомогою `generateHints()`.

---

# 4. Алгоритм роботи кнопки «Експорт»

Після натискання кнопки редактор виконує такі дії:

1. Перевіряє, чи документ збережений (`documentState.isModified == false`).

   Якщо ні — виводить повідомлення:

   > Документ має незбережені зміни. Спочатку збережіть його.

2. Генерує підказки з bitmap.

3. Запускає `solver` і перевіряє кількість розв'язків.

   Якщо задача не має єдиного розв'язку — експорт забороняється.

4. Визначає наступний номер каталогу `data-XXX`.

5. Створює каталог

```
content/data-XXX
```

6. Створює файл

```
data.js
```

7. Записує до нього всі необхідні дані.

8. Повідомляє про успішне завершення експорту із зазначенням номера створеного набору.

---

# 5. Автоматична нумерація

Редактор сам переглядає папку `content`, знаходить усі каталоги виду

```
data-001
data-002
...
```

визначає найбільший номер і створює наступний.

Наприклад:

```
data-001
data-002
data-005
```

→ буде створено

```
data-006
```

Пропущені номери повторно не використовуються.

---

# 6. Повторний експорт

Редактор **не намагається визначити**, чи є поточний експорт новою задачею або новою версією вже існуючої.

Кожне натискання кнопки **«Експорт»** створює **новий** каталог `data-XXX`.

Контроль версій і вирішення питання про заміну або видалення старих наборів залишається відповідальністю автора.

---

# 7. Подальша розробка гри

Після завершення експорту повертаємося до розробки гри.

Початок `script.js` матиме приблизно такий вигляд:

```javascript
import { getDataFolder } from "../common/url.js";
import { generateHints } from "./common/hints.js";

const CELL_EMPTY = 0;
const CELL_FILLED = 1;
const CELL_CROSSED = 2;

const gameData = {
    title: "",
    width: 0,
    height: 0,

    bitmap: [],

    rowHints: [],
    columnHints: []
};

const gameState = {
    playerBitmap: [],

    moves: 0,
    startTime: null,

    isCompleted: false
};
```

Після цього реалізується функція `initialize()`, яка:

1. завантажує `data.js`;
2. заповнює `gameData`;
3. генерує підказки з `bitmap`;
4. створює `playerBitmap`;
5. будує інтерфейс гри.
